# 模型思考模式参考：思考强度与「关闭思考」

同一个「思考强度」按钮，在不同模型上的行为差别很大：有的模型能从"完全不思考"一路调到"最高强度"，有的只有两三档，有的根本关不掉，还有的换了中转站就完全不认这个参数。

本文按模型系列整理真实支持的形态，并给出「怎么判断设置真的生效」的方法，方便你在遇到"选了没反应"时快速定位原因。

::: tip 关于本文的数据来源
表中的档位与"能否关闭"来自各厂商官方文档，并在真实渠道上逐项发请求核对过（以实际返回的思考 token 数与思考内容是否仍然出现为准）。厂商更新模型后可能有出入，遇到不一致以实测为准。
:::

## 一、三种控制形态

| 形态 | 表现 | 典型模型 |
| --- | --- | --- |
| **档位型** | 用离散档位控制思考深度：关闭 / 极低 / 低 / 中 / 高 / 极高 / 最高 中的若干档 | GPT-5 系、Claude 4.6+、Gemini 3、Grok |
| **预算型** | 用"思考 token 上限"控制，没有档位概念；部分模型把上限设为 0 即为关闭 | Gemini 2.5 系、Claude 4.5 及更早 |
| **开关型** | 只有开 / 关，没有中间档；部分模型同时提供开关与档位 | DeepSeek、Kimi、GLM、Qwen 的部分模型 |

档位数量越往上越少见：`极高` 与 `最高` 只有部分新模型支持，不是所有「支持思考」的模型都有。

## 二、各系列的真实支持情况

### Claude（Anthropic）

| 模型代际 | 形态 | 档位 | 能否关闭 |
| --- | --- | --- | --- |
| Claude 4.6 | 档位型 | 低 / 中 / 高 / 最高 | 可以 |
| Claude 4.7、4.8、5、5.5 系（含 Opus、Sonnet） | 档位型 | 低 / 中 / 高 / 极高 / 最高 | 多数可以；**Opus 5.5、Fable 5.1 思考恒开**，关闭请求会被忽略 |
| Claude 4.5 及更早 | 预算型 | 无档位 | 可以（关闭后不消耗思考预算） |

要点：

- **「极高」「最高」不是每代都有**，4.6 最高只到 `max`，没有 `xhigh`。
- Sonnet 5.5 的关闭语义特殊：关闭只在低/中/高档位下有效，极高/最高档位下会被拒绝或忽略。
- Opus 5 这一代在关闭思考时会把档位限制在「高」及以下。

### GPT（OpenAI）

| 模型 | 档位 | 关闭 |
| --- | --- | --- |
| GPT-5（含 mini / nano） | 极低 / 低 / 中 / 高 | 不支持 |
| GPT-5.1 | 低 / 中 / 高（+ 关闭） | 支持 |
| GPT-5.2、5.3、5.4、5.5 | 关闭 / 低 / 中 / 高 / 极高 | 支持 |
| GPT-5.6 系 | 关闭 / 低 / 中 / 高 / 极高 / 最高 | 支持 |
| GPT-5 Pro、5.2 Pro、5.4 Pro、5.5 Pro | 只有中 / 高 / 极高（部分仅高） | 不支持 |
| GPT-6 Astra、6.1 Sol | 低 / 中 / 高 / 极高 / 最高 | **不支持**（传「关闭」会被拒绝） |

要点：

- **「关闭」能否生效取决于接口形态**：走 `chat/completions` 风格接口时，部分服务会把「关闭」当作「低」处理；走 `responses` 风格接口时才会真正归零。若你选了关闭但仍在思考，优先在供应商设置里切到新版统一端点（Responses）再试。
- 官方 Pro 系档位很少，只有「中 / 高 / 极高」，选更低档不会更省。

### Gemini（Google）

| 模型 | 形态 | 说明 |
| --- | --- | --- |
| Gemini 3 Pro / 3.1 Pro | 档位型 | 支持 低 / 中 / 高；**不能关闭** |
| Gemini 3 系 Flash | 档位型 | 支持 极低 / 低 / 中 / 高；极低最接近"不思考"，但仍不是完全关闭 |
| Gemini 3.7 / 3.8 Flash | 档位型 | 低 / 中 / 高（**没有极低**） |
| Gemini 图像模型（如 3.1 Flash Image） | 档位型 | 只有 极低 / 高 |
| Gemini 2.5 Pro | 预算型 | 152 ~ 32768 token，**不能关闭** |
| Gemini 2.5 Flash / Flash-Lite | 预算型 | 可设为 0 关闭；Flash 0~24576，Flash-Lite 0 或 512~24576 |

要点：Gemini 3 系**不允许同时**使用档位与预算两种设置，混用会直接报错。

### 国产与第三方（走 OpenAI 兼容接口时）

| 系列 | 形态 | 关闭方式 | 备注 |
| --- | --- | --- | --- |
| DeepSeek V4 系 | 开关 + 档位 | **只有专用关闭开关有效**，"关闭"档位仍会思考 | 档位 低 / 高 / 最高 |
| Kimi K3 | 档位型 | 无（K2.5 / K2.6 为开关型，可关闭） | 档位 低 / 高 / 最高 |
| GLM 5 系 | 开关 + 档位 | 专用关闭开关有效 | 5.2 只有 高 / 最高；5.3 为 低 / 高 / 最高 |
| Qwen 3.8 系 | 开关 + 档位 | **需要与 DeepSeek 不同的开关参数**，"关闭"档位无效 | 档位 低 / 中 / 极高 |
| Grok 4.5 / 4.6 / 4.7 | 档位型 | 依赖渠道，部分渠道忽略 | 档位 低 / 中 / 高 / 极高 |
| MiniMax M3 | 开关 + 档位 | 视版本而定 | M3.1 Flash 档位 低 ~ 最高 |

要点：

- **不同厂商的"关闭"参数互不通用**：把某家的关闭方式套到另一家，常见结果是接口照样返回成功、但模型仍然思考。这类"不报错也不生效"的情况只能靠下文的方法识别。
- 中转站（聚合渠道）可能改写或用自家参数，档位与开关行为以该渠道实测为准。

## 三、怎么判断设置真的生效

看「Token 统计 → 调用记录」里的 token 明细，或在对话里看是否还有思考过程展示：

| 现象 | 含义 |
| --- | --- |
| 选了「关闭」后，本次调用的推理 token 归零、对话里不再出现思考过程 | 关闭成功 |
| 选了「关闭」后，推理 token 仍明显大于 0，或仍能看到思考过程 | **关闭未生效**：模型思考恒开，或该渠道不认这个关闭参数 |
| 选了「最高」后，推理 token 与「高」接近 | 该模型最高档只到「高」，或渠道把它降级了 |
| 档位怎么调，推理 token 都差不多 | 该渠道没有透传档位参数（常见于中转站） |

推理 token 通常单独列出（部分服务在用量里只给总数，此时只能靠"是否还有思考过程"判断）。

> 应用会自动从服务的报错文案里学习档位白名单（报错里带 `valid levels: …` / `Supported values are: …` 时），
> 学到后该渠道下的这个模型就只列真实支持的档位，不会反复撞同一个错误；换渠道会重新判断。

## 四、常见问题

**问：为什么同一个模型，换一个中转站后档位表现不一样？**
档位是否被透传、能否关闭，取决于该渠道实际使用的接口与上游账号权限。同一个模型名在不同渠道可以完全不同，见第三节的判断方法。

**问：模型名被中转站改了，识别不出档位怎么办？**
此时会列出全部档位供你手选。请先按第二节找出你的模型属于哪一档，再选择它真实支持的档位——选到不存在的档位通常不会报错，但会被静默降级。

**问：选了「极低」还是思考很久？**
「极低」不等于「关闭」。Gemini 3 系、部分国产模型的最底档仍会有思考量；要真正归零只能用「关闭」（前提是该模型支持关闭）。

**问：有的模型明明支持「最高」，选了却像「高」？**
一是该代模型本来就没有更高档（例如只有 低/中/高 的模型）；二是渠道未透传。可用第三节的方法对照。

**问：关闭思考后，之前几轮已经产生的思考内容会出错吗？**
不会。历史轮次的思考内容照常回传，服务端会忽略或兼容处理。

## 五、怎么选档位

- **日常问答、改文案、跑简单命令**：低 或 中，响应更快、费用更低。
- **改多文件、排查复杂 bug、写测试**：高 或 极高。
- **只要结果、不在乎等待与费用**：最高（仅部分模型支持）。
- **完全不需要推理的机械任务**（格式化、翻译、抽取字段）：能关就关，最省 token。
