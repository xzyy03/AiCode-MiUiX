# 默认模型

「设置 → 默认模型」里除了新会话使用的默认模型，还可以给几个特定用途单独指定模型。

## 识图模型

当前聊天模型支持视觉时，图片会直接附加到当前对话，由聊天模型分析；聊天模型不支持视觉时，才使用这里的配置建立独立识图会话。

- **跟随当前聊天模型**（默认）：独立识图会话也使用当前聊天模型，需确保模型支持图片输入。
- **指定专用模型**：独立识图会话使用指定模型，适合聊天模型不支持图片的情况。配置的供应商需已启用并填写 API Key，否则回退到当前聊天模型。

列表里每个模型旁边会标注是否支持图片输入，供你参考。注意这里**不做强制拦截**：如果你选了一个不支持图片的模型，识图会失败，AI 会收到错误信息并自行处理（通常会提示你换一个模型）。

识图的用法上有几点值得知道：

- AI 一次最多可以传入 **5 张图片**做对比分析。
- 直接附图时，继续在当前聊天中追问即可；独立识图会生成会话标识，AI 可沿用该会话追问，保留之前看过的图和问答。
- 默认清晰度与原图优先模式均优先保留不超过 **4 MiB** 的 JPEG、PNG、WebP、GIF 原文件；其他图片转为最长边不超过 **1536 像素**的 JPEG。
- 低清模式将图片转为最长边不超过 **512 像素**的 JPEG，适合节省 token。

## 生图模型

设置 `generateImage` 工具使用的模型，支持 OpenAI 和 Gemini 兼容接口。

- OpenAI 兼容接口支持尺寸、数量、画质、背景、风格和输出格式等参数。
- Gemini 兼容接口使用模型默认尺寸与分辨率；生成多张图片时会调用多次。
- 图片默认保存到 `~/.aicode/generated-images/`，也可指定工作区路径。单张图片上限 20MB，单次调用总计上限 48MB。

## 图像模型对话生图

通过 Gemini 兼容接口接入支持图像输出的聊天模型后，可直接生成图片、上传参考图，并在后续对话中继续修改生成结果。

## 子代理模型档位

AI 派发子代理时，会按任务难度选一个档位，而不是固定用同一个模型。这里定义「哪个档位对应哪个模型」：

| 档位 | 适合的活 |
| --- | --- |
| 轻量 | 只读探索、批量定位、机械改名 |
| 均衡 | 单文件修改、常规 bug 修复 |
| 强力 | 跨模块重构、疑难排查、方案设计 |

- 每档都可以选「未配置」：**只配你用得到的档位即可**，未配置的档位会自动降级（见下）。
- 每个档位可指定任意已启用提供商下的任意模型，支持按模型名搜索——接中转站时上百个模型也能找到。
- 优先级：子代理定义里写死了模型时，以定义为准（档位被忽略）；否则用 AI 选的档位。
- 降级顺序：请求的档位未配置或对应提供商被删除/停用 → 退到「均衡」档 → 仍未配置则继承当前会话模型。发生降级时，AI 会在工具结果里收到具体说明，你也能在对话里看到它按哪个模型继续。
- 删掉某个提供商时，引用它的档位会自动清空，不会留下指向空模型的配置。

## 标题总结模型

新会话发出第一条消息后，AiCode 会自动给会话生成一个标题。这里可以指定专门用于该任务的模型。

- **跟随当前聊天模型**（默认）。
- **指定专用模型**：建议选一个便宜快速的小模型，标题这种活不需要好模型。

标题生成在后台异步进行，不会拖慢你的对话。如果生成失败或者取不到结果，会保留系统按首句截断的临时标题，不影响使用。

生成标题用的提示词也可以自行修改，方式见「自定义提示词」。
